# Contributing to AgentSpaces Clojure

Thank you for your interest in contributing. AgentSpaces Clojure is an
Apache 2.0 project from Bad Monkey, Inc., and everything in this repository
stays Apache 2.0.

This repository holds the Clojure bindings only: maps, keywords, and functions
over the AgentSpaces Java libraries. Changes to the fabric itself (peering,
spaces, capabilities, the wire protocol) belong in the
[AgentSpaces core repository](https://github.com/badmonkeyai/AgentSpaces).

## Before you start

- **Questions and ideas** are welcome as [GitHub issues](https://github.com/badmonkeyai/agentspaces-clj/issues)
  or discussions. Every README section names the specification clause it
  exposes; read that clause first for anything protocol-shaped.
- **Security issues** must not be filed as public issues. See
  [SECURITY.md](SECURITY.md) for private reporting.
- **Code of conduct:** by participating you agree to the
  [Code of Conduct](CODE_OF_CONDUCT.md).

## Building

You need JDK 21 and the [Clojure CLI](https://clojure.org/guides/install_clojure).
The bindings consume the AgentSpaces Java libraries by Maven coordinates, at
the version `deps.edn` names. Until those artifacts are on Maven Central,
install the core into your local repository first:

```
git clone https://github.com/badmonkeyai/AgentSpaces.git agentspaces
mvn -f agentspaces/pom.xml install -DskipTests
```

Then, in this repository:

```
clojure -M:test            # the suite: real fleets over loopback, about fifteen seconds
clojure -T:build jar       # target/agentspaces-clj-<version>.jar, source-only, with its pom
clojure -T:build install   # the jar into ~/.m2, to try it from another project
```

Releases go to Clojars from a version tag (`v0.2.0`), through
`.github/workflows/release.yml`. Maintainers can deploy by hand with
`CLOJARS_USERNAME` and `CLOJARS_PASSWORD` (a deploy token) set:
`clojure -T:build:deploy deploy`.

## Developer Certificate of Origin (DCO)

Contributions require a [DCO](https://developercertificate.org/) sign-off:
every commit must carry a `Signed-off-by` line matching the commit author,
which `git commit -s` adds for you. Signing off certifies that you wrote the
change or otherwise have the right to submit it under the Apache 2.0 license.
A bot will check this on pull requests.

## Pull requests

- Keep PRs focused; separate refactoring from behavior changes.
- Every source file carries the Apache 2.0 header.
- Public vars carry docstrings, and a new config key gets a row in the README's
  "Config key to starter property" table.
- Tests accompany changes and run real peers over loopback. Prefer the core's
  `agentspaces-test-support` clock and network over sleeps.
- Keep the bindings thin: they translate data to the Java API and back, and add
  no behavior the Java libraries lack.

### Submit a pull request

Should you create an issue first?
No, just create the pull request and use the description to provide context and motivation, as you would for an issue.
You only have to create an issue if you want to start a discussion first.

Please don't submit pull requests:

* With GitHub accounts managed by autonomous AI bots
* For already assigned issues (as the assignee is or plans to work on it)
* For straightforward or polish-style changes, feel free to create a ticket on those or send a note to 'oss@badmonkey.ai' if you've found polish issues you are passionate about.

The pull request title is used to generate the changelog so please use a short and descriptive text with types or filenames enclosed in backticks.
If your pull request is related to an issue, please mention the related issue with its number in the PR description (not in the title), for example "Fixes #123".

Before submitting a pull request:

* Add new tests that exercise the code you have added or modified
* Run the tests locally with `clojure -M:test`
* If possible run integration tests related to the part you modify (see related documentation below)
* Any code needs to be carefully reviewed by a human, especially when generated by a coding agent

## Commit message

A commit message should include a short title (if possible less than 50 characters) starting with an uppercase verb.
The title should *not* include prefixes like `fix:`, `feat:` or `docs:` or the issue/PR number.

- ✅ Add Contribution Guidelines
- ❌ GH-123: Add Contribution Guidelines
- ❌ docs: Add Contribution Guidelines
- ❌ Add Contribution Guidelines (#123)

The commit description should be wrapped at approximately 72 characters.

Commit messages should allow discoverability of related issues and PRs [by linking them](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue#linking-a-pull-request-to-an-issue-using-a-keyword) after the description with for example `Closes #123` if the issue number is 123.
That allows bi-directional navigation from the commit to the issue/PR, but also in the other way around as related mentions are added by GitHub.

All commits must include a __Signed-off-by__ trailer at the end of each commit message to indicate that the contributor agrees to the Developer Certificate of Origin.

For additional details, please refer to the blog post [Hello DCO, Goodbye CLA: Simplifying Contributions to Spring](https://spring.io/blog/2025/01/06/hello-dco-goodbye-cla-simplifying-contributions-to-spring) that Bad Monkey is aligning to. 

Please find below the example of a typical commit message:

```text
    Add Contribution Guidelines

    This commit adds CONTRIBUTING.md describing the Contribution
    procedure, mentions Contribution Guidelines in the README.md and
    mentions CODE_OF_CONDUCT in the README.md.

    Fixes #123

    Signed-off-by: Firstname Lastname <username@users.noreply.github.com>
```

If you want to only reference some issue or PR without closing it, you can use `See #123`.
Annotations should be enclosed in backticks to avoid mentioning potential related GitHub users.  

If the commit has both an issue and a PR associated, the AgentSpaces Clojure committer merging the PR should reference both the issue and the PR and ensure the title does not contain the number of the PR, for example with an issue #123 and a PR #456:
```text
    Add Contribution Guidelines

    ...

    Fixes #123
    Closes #456

    Signed-off-by: Firstname Lastname <username@users.noreply.github.com>
```

## Source code style

Follow the [Clojure Style Guide](https://guide.clojure.style). Namespaces stay
small and data-first: config maps in, maps out, the Java objects reachable
through metadata and the system map for interop.
